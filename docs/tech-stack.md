# 技术选型与架构说明

## 总体架构

```
用户浏览器
    │
    ▼
┌─────────────────────────────────────────┐
│              Nginx (1Panel)              │
│       反向代理 · 静态资源 · SSL           │
├─────────────────────────────────────────┤
│   /        │   /api/*    │   /admin/*   │
│ Astro SSR │ Express API │ React SPA    │
│ (Node.js) │  (Node.js)  │ (静态文件)    │
├─────────────────────────────────────────┤
│             MySQL 8.0                    │
├─────────────────────────────────────────┤
│         本地文件存储 (图片/上传)          │
└─────────────────────────────────────────┘

双模式数据层：
┌──────────────┐     ┌──────────────┐
│  生产模式     │     │  静态模式     │
│  fetch API  │     │  import mock │
│  SSR 渲染   │     │  纯静态打包   │
└──────┬───────┘     └──────┬───────┘
       │                    │
       ▼                    ▼
   src/lib/data.ts (统一数据接口)
```

## 关键技术决策

1. **双模式构建**：生产环境走 Astro SSR + Express API + MySQL；提交/演示模式通过 `ASTRO_MODE=static` 打包为纯静态站点，数据从 Mock 数据层读取
2. **统一数据接口**：`src/lib/data.ts` 封装数据获取，内部根据运行模式切换 API 调用 / Mock 数据，页面代码无需感知
3. **设计参考 Mizuki**：布局和功能对齐 Mizuki 博客主题，但视觉风格做差异化（二次元动漫风而非 Material Design 3）
4. **独立后台**：管理后台为独立 React SPA，与博客前端分离部署
5. **Prisma ORM**：类型安全 + 自动迁移，减少手写 SQL
6. **Expressive Code**：替代 Shiki，提供更丰富的代码块功能（标题栏、行号、差异高亮）
7. **JWT 认证**：无状态认证，适合前后端分离架构
